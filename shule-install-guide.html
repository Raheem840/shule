Part 0 · New — Do This First
Pre-Requisites — Getting the Local Anon Key
Before you can build the school's Docker image you need the Supabase local anon key. You get it by running Supabase self-hosted on your own machine first, reading the key from the .env file, then using it in the build command.
Do At Home First
💡
Why does this step exist? The local anon key is generated when you set up Supabase self-hosted Docker. The school machine does not have it yet — it is in the .env file inside the Supabase Docker folder that you run at home or configure before the visit. You copy this key and bake it into the school's Docker image before you go on site.
0.1 Install Docker on Your Machine (Home / Office)

This runs on your laptop, not the school's server. Docker is what runs Supabase locally.

Windows
Download Docker Desktop from docker.com/products/docker-desktop
Run the installer → follow prompts → restart your machine when asked
Open a terminal (Command Prompt or PowerShell) and verify: docker --version → should print a version number
Also verify: docker compose version → should print a version
Ubuntu / Linux
bash
# Install Docker
sudo apt update && sudo apt install -y docker.io docker-compose
sudo systemctl enable docker && sudo systemctl start docker
sudo usermod -aG docker $USER

# Log out and back in, then verify
docker --version
docker compose version
0.2 Clone the Supabase Self-Hosted Repository

This gives you the Docker compose setup for running Supabase locally.

bash
# Clone the Supabase self-hosted repo
git clone https://github.com/supabase/supabase
cd supabase/docker

# Copy the example env file
cp .env.example .env
0.3 Configure the .env File

Open the .env file in a text editor. You need to change a few key values before starting:

bash
# Open .env in your editor
# On Windows: use Notepad or VS Code
# On Linux/Mac:
nano .env

Inside the .env file, find and update these values:

Key in .envWhat to set it toWhy
POSTGRES_PASSWORDA strong password you choose (e.g. ShuleSchool2025!)Secures the database
JWT_SECRETA long random string (32+ chars). Generate one at supabase.com/docs/guides/self-hosting/docker#generate-api-keysSigns all JWT tokens
ANON_KEYGenerated from your JWT_SECRET (see step 0.4)Public key for the frontend
SERVICE_ROLE_KEYGenerated from your JWT_SECRET (see step 0.4)Admin key — server only
SITE_URLhttp://192.168.1.100The school's local server URL
0.4 Generate and Get the Anon Key

This is the step that was missing. The anon key does not exist until you generate it from your JWT_SECRET. Here is exactly how to get it.

Method 1 — Use the Supabase key generator (recommended):

Go to: supabase.com/docs/guides/self-hosting/docker#generate-api-keys
Paste your JWT_SECRET from the .env file into the form on that page
Click Generate JWT — it produces two keys: anon key and service_role key
Copy the anon key — paste it into the ANON_KEY= line in your .env file
Copy the service_role key — paste it into the SERVICE_ROLE_KEY= line. Keep this secret — never put it in the frontend.
Save the .env file. Also save both keys somewhere safe (e.g. a password manager) — you will need the anon key in Part 1.

Method 2 — Read the default key (quick but less secure):

⚠️
The default anon key in .env.example works but uses a shared public JWT_SECRET. Anyone who knows the default can craft tokens. For any real school installation, always generate your own key using Method 1 above.
bash
# Read the anon key from your .env file
grep ANON_KEY .env

# Output will look like:
# ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJpc3...

# Copy everything AFTER the = sign — that is your local anon key
✓
Save this anon key now. You will paste it into the npm run build:school command in Part 1 Step 1.2. Without it you cannot build the school's Docker image.
0.5 Start Supabase Locally and Verify It Works

Start the local Supabase stack on your machine to confirm everything is configured correctly before you go to the school.

bash
# Make sure you are in the supabase/docker folder
cd supabase/docker

# Start the full stack
docker compose up -d

# Wait about 30 seconds then check all containers are running
docker compose ps

# You should see services like: db, auth, rest, realtime, storage, kong
# all showing status: running

# Open Supabase Studio in your browser
# http://localhost:3000

# You should see the Supabase Studio dashboard
# This confirms the stack works
All containers show running in docker compose ps
Supabase Studio opens at http://localhost:3000
Anon key is saved (from step 0.4) — ready to use in build command
ℹ️
You can now stop the local stack on your machine with docker compose down. The school's server will run its own instance from the USB. The anon key you extracted is what matters.

Part 1 · Before You Leave Home
Prepare the USB Installation Package
Build the school's Docker image using the anon key from Part 0, save all Docker images offline, and copy everything to the USB drive.
⏱ Do at Home
1.1 Format and Prepare the USB Drive

Use a USB drive of minimum 32GB. The Docker images are large.

Windows
Insert USB drive → Open File Explorer → right-click the USB drive → click Format
File system: exFAT · Volume label: SHULE-INSTALL · Quick Format: checked → Start → OK
Wait for format to complete → USB is ready
Linux
bash
lsblk
# Find your USB device (e.g. sdb)
sudo mkfs.exfat -n SHULE-INSTALL /dev/sdX1
1.2 Build the School's Docker Image

Open terminal in your Shule project folder. Replace YOUR_ANON_KEY with the key you saved in step 0.4:

bash
# Navigate to your Shule project folder first
cd path/to/shule

# Build the school image
# Replace YOUR_ANON_KEY with the key from step 0.4
npm run build:school "New Youth Comprehensive School" \
  http://192.168.1.100:8000 YOUR_ANON_KEY local
✓
When complete you will see: ✓ Build complete — Saved to: shule-install/shule-new-youth-comprehensive-school.tar
1.3 Pull and Save Supabase Docker Images

This downloads all required images and saves them offline so no internet is needed at the school.

bash
npm run usb:prepare "New Youth Comprehensive School" \
  http://192.168.1.100:8000 YOUR_ANON_KEY local
⚠️
Watch for errors. If any image fails to download, re-run before going to the school. Also copy the supabase/docker/.env file to your USB — you will need it at the school to start Supabase with the correct keys.
1.4 Verify the shule-install/ Folder

Confirm every file is present. If anything is missing, stop and fix it before going.

shule-install/ ├── README.txt ✓ ├── install.sh ✓ ├── docker-compose.school.yml ✓ ├── nginx.conf ✓ ├── shule-new-youth-comprehensive-school.tar ✓ ├── shule-new-youth-comprehensive-school.env ✓ ├── supabase-images/ │ ├── postgres--15-alpine.tar ✓ │ ├── nginx--alpine.tar ✓ │ └── kong--2.8.1.tar ✓ └── migrations/ ├── 00001_initial_schema.sql ✓ ├── 00002_rls_policies.sql ✓ ├── 00003_functions_triggers.sql ✓ ├── 00004_jwt_hook.sql ✓ └── base.sql ✓ Also copy from supabase/docker/: └── .env ← copy this file to USB too — needed to start Supabase at school ✓
1.5 Copy shule-install/ to the USB Drive
Windows
Open File Explorer → navigate to your Shule project folder → right-click shule-install → Copy
Open the USB (SHULE-INSTALL) → right-click → Paste. Also copy the supabase/docker/.env file to the USB root.
Wait for copy to complete (10–20 minutes — Docker images are large)

ls -lh /media/yourname/SHULE-INSTALL/
sudo umount /media/yourname/SHULE-INSTALL

Part 2 · At the School
Server Machine Setup and Installation
Set up the server PC, install Ubuntu, mount the USB, and run the one-command installer.
⏱ ~45 min
2.1 Set Up the Server Machine
ℹ️
Minimum specs: 8GB RAM · 256GB SSD · Intel i5 or better · Ethernet port or strong WiFi. This PC stays at the school permanently as the server.

Install Ubuntu Server 22.04 LTS if not already installed:

Download Ubuntu Server 22.04 ISO at home (ubuntu.com) → flash to a second USB using Rufus (Windows) or Balena Etcher
Boot the school PC from that USB → press F2, F8, F12, or Delete during startup to enter BIOS → set USB as first boot device
Ubuntu installer → Language: English · Keyboard: English (US) · Type: Ubuntu Server (not minimized)
Network → connect to school WiFi or ethernet · Storage → Use entire disk → Done → Continue
Profile: Name shule · Server name shule-server · Username shule · Set strong password and write it down
Install OpenSSH: Yes · Featured snaps: skip → Done · Wait ~15 min → reboot → log in
2.2 Connect and Mount the SHULE-INSTALL USB
bash
# Plug in the SHULE-INSTALL USB drive
lsblk
# Find USB device (e.g. sdb → sdb1)

sudo mkdir -p /mnt/shule-usb
sudo mount /dev/sdb1 /mnt/shule-usb

# Verify the files are there
ls /mnt/shule-usb/shule-install/
2.3 Copy Install Files to the Server
bash
sudo cp -r /mnt/shule-usb/shule-install/ /opt/shule-install/

# Also copy the Supabase .env file
sudo cp /mnt/shule-usb/.env /opt/shule-install/supabase.env

cd /opt/shule-install
sudo chmod +x install.sh
ls -la
2.4 Run the Install Script
bash
sudo bash install.sh

Runs for approximately 15–20 minutes. Watch each step tick off:

→ [1/8] Installing system dependencies... ✓ → [2/8] Loading Docker images... ✓ → [3/8] Configuring network... ✓ → [4/8] Starting Shule services... ✓ → [5/8] Setting up database schema... ✓ → [6/8] Loading base data... ✓ → [7/8] Configuring web server... ✓ → [8/8] Configuring backups... ✓
ErrorFix
Docker image not foundRe-check USB copy was complete — files may have been missed
Port 80 already in useRun sudo systemctl stop apache2
Database connection refusedWait 30 more seconds and retry the database steps manually
2.5 Verify the System Is Running
Open any device on the school WiFi → browser → http://192.168.1.100 → Shule login page appears
Open http://192.168.1.100:3000 → Supabase Studio dashboard appears

If either does not load:

bash
sudo docker ps
sudo systemctl status nginx
sudo docker compose -f /opt/shule/docker-compose.school.yml logs

Part 3 · Supabase Studio — Manual Steps
Database Auth Configuration
Open Supabase Studio at http://192.168.1.100:3000 and complete these in order. These cannot be automated.
⚠️ Critical
3.1 Register the JWT Hook
🚨
Most critical step. Without this, nobody can log in to Shule. Do not skip.
In Supabase Studio sidebar → Authentication → Hooks
Find Custom Access Token Hook → click the toggle to Enable
In the dropdown select: public.custom_access_token_hook
Click Save → green confirmation appears

Verify in SQL Editor:

sql
SELECT routine_name, routine_schema
FROM information_schema.routines
WHERE routine_name = 'custom_access_token_hook';
-- Should return 1 row with routine_schema = public
3.2 Create the IT Admin Auth User
Authentication → Users → click Add User
Email: itadmin@nycs.ac.ug (replace nycs with school short name) · Password: Shule@2025 · Auto Confirm: checked
Click Create User → copy the User ID (the UUID in the ID column) — paste it somewhere safe
3.3 Create the IT Admin Staff Row
sql
-- First get the school_id
SELECT id, school_name FROM school_profile;
sql
-- Insert IT Admin staff row
INSERT INTO staff (
  school_id, first_name, last_name,
  role, auth_user_id, is_active
) VALUES (
  'PASTE_SCHOOL_ID_HERE',
  'Admin', 'IT',
  'it_admin',
  'PASTE_AUTH_USER_ID_HERE',
  true
);
✓
Should say Success. 1 row affected. Verify the link: SELECT s.first_name, s.role, u.email FROM staff s JOIN auth.users u ON u.id = s.auth_user_id WHERE s.role = 'it_admin';
3.4 Verify the Full Login Flow
New tab → http://192.168.1.100 → login with itadmin@nycs.ac.ug / Shule@2025
You land on the IT Admin dashboard with correct sidebar — login confirmed working
ErrorCauseFix

School Profile Setup
IT Admin configures the school identity, academic year, departments, and creates all senior staff accounts.
⏱ ~30 min
4.1 IT Admin Configures the School
Log in as IT Admin → go to School Settings → upload logo, set full name, short name, motto, brand color, address, phone → Save

Settings → Departments → add Sciences, Humanities, Languages, Technical → Save each
4.2 Create Senior Staff Accounts

Go to Staff Management → Register Staff. Create accounts in this order:

Secretary — secretary@nycs.ac.ug · Role: Secretary
Principal — principal@nycs.ac.ug · Role: Principal
Deputy Principal — deputy@nycs.ac.ug · Role: Deputy
Director of Studies — dos@nycs.ac.ug · Role: DoS
Bursar — bursar@nycs.ac.ug · Role: Bursar
✓
Each account is created with password Shule@2025 via the create-staff-auth-user Edge Function automatically.

Part 5 · Secretary
Staff Registration
Secretary logs in and registers all teaching staff using the 4-step wizard.
⏱ ~45 min
5.1 Secretary Logs In
Open http://192.168.1.100 on Secretary's device → login: secretary@nycs.ac.ug / Shule@2025
Secretary is prompted to change password on first login
5.2 Register All Teaching Staff

Go to Staff → Register Staff. For each teacher, complete all 4 steps:

Step 1 — Personal info: Full name, date of birth, gender, National ID, phone, email. Photo is optional at this stage.
Step 2 — Professional info: Staff number (auto-generated), Role (Teacher or Class Teacher), Department, Subjects, Classes assigned
Step 3 — Qualification level: Select from Uganda MoES dropdown. System warns if below minimum for their class level.
Step 4 — Documents: Upload NIN (required for new staff). Mark as "existing staff" to skip mandatory uploads for staff already in the system.
Submit — auth account auto-created, credentials auto-generated
