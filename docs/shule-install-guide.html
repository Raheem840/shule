🧭 Choose Your Path — Read This First

Every school takes Part 0 (prerequisites), then splits by connectivity, then rejoins at Part 7 (School Setup) for the rest of go-live. Pick the school's path now so you skip the parts that don't apply to them.

🏠 Local
No reliable internet at the school, ever. Everything — database, auth, storage, edge functions, frontend — runs on a server PC that stays on-site. Needs one in-person visit with a prepared USB.
Parts 1 → 2 → 3
🔀 Hybrid
Same on-site server as Local, for day-to-day reliability when the internet drops, but also wired to a cloud Supabase project so data isn't stranded on one machine. Same on-site steps as Local, plus a cloud project alongside.
Parts 1 → 2 → 3 + Part 4, Part 6
☁️ Cloud
Reliable internet at the school. No server hardware, no USB, no site visit for the technical setup — everything runs on Supabase's cloud and is deployed to the web via Vercel. Fastest to set up remotely.
Part 4 → Part 6
ℹ️
All three paths then continue with Part 5 (bringing in the school's existing records) and Parts 7–11 (school profile, staff registration, device setup, training, handover) — those are identical regardless of which path you took to get the backend running.

0.1 Install Docker and Node.js on Your Machine

Docker is only needed if you'll ever do a Local or Hybrid install (it builds and packages the on-prem stack). Node.js is needed for every path — it runs the npm scripts that build and deploy Shule.

Windows
Download Docker Desktop from docker.com/products/docker-desktop → install → restart when asked
Download Node.js LTS from nodejs.org → install with default options
Open a terminal and verify: docker --version, docker compose version, node --version, npm --version — all should print version numbers
Ubuntu / Linux
bash
# Docker
sudo apt update && sudo apt install -y docker.io docker-compose-v2
sudo systemctl enable docker && sudo systemctl start docker
sudo usermod -aG docker $USER

# Node.js LTS (via nvm is easiest)
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
nvm install --lts

# Log out and back in, then verify
docker --version && node --version && npm --version
0.2 Clone the Shule Repo and Install Dependencies
bash
git clone https://github.com/Raheem840/shule.git
cd shule
npm ci

All the commands in this guide (npm run usb:prepare, npm run install:school, etc.) are run from inside this shule/ folder.

0.3 Install the Supabase CLI (Cloud / Hybrid Path Only)

Skip this if the school is pure Local — the on-prem installer doesn't use the Supabase CLI at all. Any school with a cloud Supabase project needs it to push the schema.

# Or via npm, any OS

2.3 Confirm the School's Router Subnet

Don't skip this — it's the single most common reason a Local install "disappears" after setup. install.sh hardcodes the server's static IP to 192.168.1.100/24 with gateway 192.168.1.1. If the school's router actually hands out a different range (e.g. 192.168.0.x or 10.0.0.x), the server puts itself on a network segment none of the school's devices can reach — the install will still finish "successfully" and then nothing loads.

On any device already connected to the school WiFi, check its assigned IP (e.g. Android/iOS WiFi settings, or ipconfig/ifconfig) — confirm it starts with 192.168.1.
On a phone: Settings → WiFi → (tap the connected network) → IP address. A matching result looks like 192.168.1.47. A mismatch — the case to fix — looks like 192.168.0.23 or 10.0.0.15.
If it doesn't match, either reconfigure the router's LAN range to 192.168.1.0/24 in its admin panel (simplest, and matches every URL printed elsewhere in this guide), or edit the addresses/gateway4 values in the netplan block inside install.sh (search for 01-shule-static.yaml) to match the router's actual range before running it
Also check the router's DHCP pool doesn't include .100 — if it can still hand that address to another device, you'll get an intermittent IP conflict. Either shrink the DHCP pool to end before .100, or add a DHCP reservation/exclusion for it, in the router's admin panel

5.1 Schema vs. Data — What Already Happened
ℹ️
Part 4.2's npm run install:school already migrated everything except data — full schema, every RLS policy, every trigger, all 15 edge functions. Replace the example rows with the school's real records (in Excel, Google Sheets, or any spreadsheet tool) — keep the header row exactly as downloaded
Upload the filled CSV → the app shows a preview: matched rows, rows needing the correct admission-number year, and any format errors
For records from a prior school year: the import reserves each admission number safely under load using the same locking the live registration wizard uses — no collision risk even with a large concurrent import
If a CSV row already has an admission_number filled in, it must match the format STU/YYYY/00000001 exactly — anything else is rejected with a clear reason rather than silently accepted
Accepted: STU/2024/00000037 (an S3 student who joined in 2024, being backfilled). Rejected with a reason shown in the failed-rows list: STU/2024/37 (not zero-padded to 8 digits) or 2024/00000037 (missing the STU/ prefix).
Review the failed-rows list (if any) → fix in the spreadsheet → re-upload just those rows → confirm import

Log in as Bursar → Fee Import page — this is a separate flow from student/staff import, for bringing in each student's opening balance from the school's old fee ledger.

Download the fee payments template, fill in student name, class, amount paid — the app matches each row to an already-imported student by admission number first, then by name + class
Columns: admission_number,student_name,class_name,stream_name,fee_type,term,year,amount_paid,amount_due,payment_date,receipt_number,notes. Matched by admission number (fastest, skips name matching entirely): STU/2026/0002,Brian Ssemwanga,S.1,East,Tuition,1,2026,450000,450000,2026-02-01,REC-002,Term 1 full payment. Resolve every flagged row in the review dropdown before confirming

Audit log entry for that row: matched_by: admission_number, amount_paid: 450000, balance: 0, matched_class: S.1 East, source_row: 2.
